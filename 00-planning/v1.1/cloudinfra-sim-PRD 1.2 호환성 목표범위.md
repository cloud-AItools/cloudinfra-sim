| 연결 문서 | PRD-1 기능 계약, PRD-2 자체 테스트·Coverage, PRD-4 AC-01 ~ AC-19·D2·D5·D7·D9·D13 |

## 1. 프로젝트 범위와 판정 단위

현재 범위는 시뮬레이터 구성과 프로젝트 내부 자체 테스트까지이다. CMP 매뉴얼은 기능 아이디어와 우선순위를 선정하는 참고 자료이다. CMP 소스 분석, 실제 CMP 연결·등록·상품 Workflow 시험, CMP 상품 제약 구현은 수행하지 않는다. 실환경 Trace 수집·Record·실환경 Differential Test도 현재 완료 조건에서 제외하고 향후 항목으로 보류한다(D5·D13).

하나의 자체 검증 조합은 다음을 고정한다.

| 요소 | 판정 대상 | 결정 위치 |
|---|---|---|
| ① 테스트 도구 | 자체 테스트 클라이언트·공개 SDK와 버전. 특정 CMP 제품·SDK에 종속시키지 않음 | D2 |
| ② 시뮬레이션 기능 | 선정한 기능·필드·행위·오류 및 이를 정의하는 FR/TR/NFR ID. CMP 기능 ID는 참고 연결만 유지 | D2, TR-COV-0103 |
| ③ 제품 버전·빌드 | 첫 조합: vCenter 7.0 U3w(7.0.3.02500, 빌드 24927011) + NSX-T 3.2.4.3(빌드 24942842) | D1 |
| ④ API 집합 | 공식 명세와 승인 범위에 따라 선정한 Coverage Matrix 행. 시험에서 미관찰된 API도 승인 범위에 남김 | TR-COV-0101, TR-COV-0102 |
| ⑤ 자체 시나리오 | ②·④를 검증하는 정상·오류·상태 전이·SDK·E2E 시나리오 | PRD-2, TEST_STRATEGY.md |

①~⑤ 또는 구현·계약이 바뀌면 영향받는 증거를 무효화하고 재검증한다. 제품 버전 범위는 vSphere/vCenter 7.0 U2 이상(8.x 포함, 9 제외)과 NSX-T 3.x이며, 결과는 시험한 특정 조합에만 적용한다.

**현재 판정:** 적용 요구사항의 자체 시험·검토가 통과하면 '승인 범위 자체 테스트 통과'로 표시한다. API 검증 상한은 `Integration Tested`이다. 이는 `CMP Verified`, `Reference VMware Verified` 또는 실제 제품과의 '100% 호환'을 뜻하지 않는다. AC-20은 향후 외부 검증을 별도 승인할 때만 적용한다.

## 2. 범위 선정·제외 원칙

1. **CMP 기능과 구현 의무를 구분한다.** 참고 기능 하나를 선택하더라도 그 상품의 전체 옵션·제약을 자동 채택하지 않는다. 시뮬레이션할 API·필드·행위와 제외할 부분을 명시한다.
2. **공식 계약에서 기대값을 정한다.** WSDL/OpenAPI·제품 문서·공개 SDK에서 대상 버전 근거를 기록한다. 시뮬레이터 자체 응답을 정답으로 복사하지 않는다.
3. **미관찰은 미사용이 아니다.** 승인된 API·오류 경로가 자체 시험에서 호출되지 않았으면 '미관찰/미검증'으로 남기고 해당 게이트를 통과시키지 않는다. 제외는 D2·D9 결정 사유를 남긴 뒤 범위와 추적표를 함께 변경한다.
4. **CMP 상품 제약은 범위 밖이다.** 과금·약정·할당량·신청 제한·프로젝트 승인·콘솔 상태·서비스 존별 수량 제한은 구현·시험하지 않는다. 같은 종류의 제한이라도 VMware API 계약의 제한은 공식 근거를 별도로 확인해 검증한다.
5. **API로 관찰되는 논리 상태만 다룬다.** 게스트·패킷·물리 회선의 실제 실행, CMP 내부 서비스는 제외한다. 게스트 초기화 등의 API를 선정하면 논리적 요청·상태·Task만 모델링한다(PRD 개요 §1.3).
6. **범위를 넓히기 전에 의존성을 배정한다.** 추가 기능의 FR, 주 WP, 목표 단계, 자체 시험을 함께 정하며, 참고 목록만으로 구현 완료나 시험 통과를 판정하지 않는다.

### 3.2 계층 B·C와 제외 항목

계층 B(45개)는 VM 네트워크 연동, NAT, Public IP, IGW, 라우팅 조회, SG, Gateway Firewall, LB 후보이다. 계층 C(58개)는 1.1의 확장 분류다. 개별 API를 채택하는 단계에서 새 FR·자체 시험·WP를 등록한다. NSX-T 3.x의 LB 후보는 유지하되 실제 API 스펙의 기능만 선정한다.

NAT·Gateway Firewall·LB·DNS Forwarder·Static Route·IP Pool 등 미정의 영역은 1.1 §18을 참고한다. 후보라는 이유로 자동 신설하거나 Phase 2b를 차단하지 않으며, 채택된 범위의 FR·시험 미배정은 종료 게이트를 차단한다.

기존 범위 외 후보 18개(VS-06·VS-28·AS-06·COM-05, DR-01~07, BK-01~05, TGW-03·DC-03)는 현재 구현하지 않는다. 추가로 AS-01의 CMP 내부 템플릿 저장, SG-11·FW-10의 실제 패킷 로그처럼 API 대상이 없는 부분도 제외한다. 참고 목록의 역사적 분류·개수는 유지하며 실제 적용 여부는 추적표에 따로 기록한다.

## 4. 자체 검증 판정 기준

| 기준 | 조건 | 증거·완료 기준 |
|---|---|---|
| F1 | 승인 API·필드·행위·오류·버전과 제외 근거가 Coverage Matrix·FR·자체 시험에 연결됨 | 공식 계약 근거, D2·D9 결정, TR-COV-0103, AC-03·AC-19 |
| F2 | 요청·응답 스키마, 상태 코드, SOAP Fault, 버전별 필드가 선정 계약과 일치 | Contract·선정 SDK 시험, TR-COV-0301·0304, AC-16·AC-17 |
| F3 | 생성→조회→수정→삭제, Task·Realization, API 간 상태 일관성이 유지됨 | Stateful·자체 E2E, TR-COV-0302·0307·0309 |
| F4 | 공식 VMware 계약의 사전조건·입력·Revision·오류를 재현함. CMP 상품 제약은 제외 | 기본 Negative와 후속 장애 자체 시험, TR-COV-0303·0308 |
| F5 | 적용 대상 기능·비기능 시험이 선정 SDK·버전·Fixture에서 통과함 | 요구사항별 시험 보고서·로그·Footprint·설치 결과, AC-01 ~ AC-19 |
| F6 (보류) | 향후 별도 승인한 실제 CMP·실환경 비교 | 현재 범위에서 제외 — D5·D13, AC-20 |

F1~F5를 충족하면 현재 범위의 자체 검증을 완료한다. Phase 2b는 MVP 대상, Phase 5는 전체 적용 대상의 기준으로 판정한다. 실환경 Trace는 F1~F5의 필수 입력이 아니다. 자체 호출 기록은 실행 증거로 연결하며 미실행·실패·무효화 항목을 통과로 처리하지 않는다.

'자체 테스트 100% 통과'를 표기할 경우 승인 범위의 전체 시험 수·통과 수·제외 수와 근거를 함께 표시한다. 외부 제품과의 '100% 호환' 표현은 현재 결과에 사용하지 않는다.

## 5. 기능과 자체 시나리오 연결

| 자체 시나리오 | 기본 검증 범위 | 추가 후보 처리 |
|---|---|---|
| Scenario 01 API 연결 및 환경 인식 | vCenter·NSX 인증, 버전·환경 조회 | CMP 등록 절차 제외 |
| Scenario 02 인벤토리 동기화 | VM 조회, 속성 변경·감시, ID 유지 | 승인한 조회 API만 포함 |
| Scenario 03 VM 생성 | VM Create·Task·관계·인벤토리 | Clone/배포/Customization은 D7 채택 시 확장 |
| Scenario 04 VM 변경 | CPU·메모리·사전조건·상태 일관성 | 디스크·VM 재시작(Reset·Guest Reboot) 등 채택 시 각각 성공 기준 추가 |
| Scenario 05 VM 삭제 | 전원 조건·삭제 Task·고아 참조 검사 | CMP 삭제 보호·상품 해지 제한 제외 |
| Scenario 06 NSX Segment | CRUD 계약·Revision·정상 Realization | Tier-1 등 D9 채택 시 확장 |
| Scenario 07 Security Policy | Group·Service·Rule·Revision | 상품 SG 개수·신청 제한 제외 |
| Scenario 08 교차 시스템 | Segment–Network–VM 관계·삭제 정합 | 선정한 논리 관계만 검증 |
| Scenario 09 장애와 복구 | 실패 주입·자체 클라이언트 재시도·중복 방지 | 실제 CMP 보상 로직 시험 제외 |
| Scenario 10 세션 만료 | 만료 응답·자체 클라이언트 재인증 | 실제 CMP 세션 관리 구현 시험 제외 |
| 추가 후보 N1/N2/N3 | 외부 연결 API / Gateway Firewall / LB | 채택 시 PRD-1 FR·PRD-2 TR·PRD-4 WP를 신설·연결. 현재 자동 적용하지 않음 |

참고 기능 ID 하나가 여러 API·오류 경로를 포함하면 자체 시험을 각각 연결한다. 기존 시나리오 이름만 연결하고 시험하지 않은 기능까지 통과로 집계하지 않는다.

## 6. 자체 검증 조합 계획

| 조합 | 기능·버전 | 목표 상태 | 시점 |
|---|---|---|---|
| C-1 | PRD MVP ● 및 채택된 ○, D1 첫 기준 조합 | Integration Tested, MVP 자체 검증 완료 | Phase 2b |
| C-2 | C-1과 같은 버전에서 추가 승인한 시뮬레이션 API | Integration Tested, 단계별 자체 검증 | Phase 3~5 |
| C-3 | 추가 승인 기능·버전 조합 | 각 조합의 Integration Tested | 해당 구현 단계 |
| C-n | D1 범위 내 추가 버전·빌드 및 선정 SDK | 자체 계약·버전 간 Differential Test 통과 | Phase 4b 이후 |

여기서 버전 간 Differential Test는 두 시뮬레이터 프로파일의 응답을 공식 버전별 계약에 대조하는 자체 시험이다. 실환경 비교나 AC-20 달성을 뜻하지 않는다. 결과에는 API 범위·제품 버전·빌드·SDK·Fixture·증거 일자·프로파일/구현 식별자를 공개한다.
